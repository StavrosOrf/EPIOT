# System overview

EPIOT is a classic three-tier web application: a static single-page frontend, a Flask backend that
exposes a small JSON API, and a SQLite database with the SpatiaLite extension for geometry. Batch
jobs fill the database ahead of time; a few external services provide map tiles, geocoding, prices,
power-mix data and optimisation.

## Technology stack

| Layer | Technology | Role |
|---|---|---|
| Web framework | Flask, Werkzeug | Routing, blueprints, templates |
| ORM & migrations | SQLAlchemy 2, Flask-SQLAlchemy-Lite, Alembic (Flask-Alembic) | Models, sessions, schema versions |
| Spatial | SpatiaLite, GeoAlchemy2, Shapely, GeoPandas, geojson | Point geometries, `ST_Within` queries, data import |
| Numerics | NumPy, Polars, pandas, SciPy | Profile simulation, KPIs, sampling |
| Optional ML | PyTorch, scikit-learn (`--extra ml`) | Session prediction (in development) |
| Map | Leaflet 1.9, Leaflet.draw, leaflet.heat | Map, drawing tools, heatmap helper |
| Geometry (browser) | Turf.js, martinez-polygon-clipping | Polygon validation, incremental loading |
| Charts | Plotly.js 2.35 | All charts |
| UI | Bootstrap 4.5, Flatpickr, Font Awesome, Inter | Layout, tooltips, date pickers, icons |
| Export | SheetJS (xlsx) | Excel report in the browser |
| Tooling | uv, pytest | Environment, tests |

## Design choices

**Precomputed sessions, on-demand profiles.** Sessions are generated by a batch job; profiles and
KPIs are computed per request from the stored sessions. This keeps requests deterministic and lets
the same sessions be viewed under any strategy.

**One request per area.** The browser sends independent requests for each area and draws them once
all have returned. Failures are reported per area.

**Incremental marker loading.** The browser remembers which parts of the map it has already
requested and only asks for the difference (see {doc}`../user-guide/map`).

**Stateless backend.** The server keeps no per-user state; drawn areas, results and the report live
in the browser.
