# Known limitations

EPIOT is a research prototype. This page lists the modelling simplifications and implementation
quirks that affect how results should be read. Each entry names where the behaviour comes from, so it
can be checked against the code and removed from this page when fixed.

## Load and flexibility profiles

```{list-table}
:header-rows: 1
:widths: 28 52 20

* - Limitation
  - Effect
  - Source
* - **Local simulators omit overnight load; session query misses some overnight sessions**
  - The departure step is computed with the arrival day's offset, so a session ending the next day gets a departure step before its arrival and is skipped. Sessions that start on $D-1$ and end on $D$ are also not selected by the query. Night-time load is under-represented. The ReFlex adapter now handles overnight sessions passed to it, but the selection query remains unchanged.
  - `aggregators.py`, `views.get_aggregate_load`
* - **Remainder energy is under-counted**
  - The partial step after the full-power block adds $(E \bmod P\Delta t)/6$ kW instead of $6\,(E \bmod P\Delta t)$ kW, so up to one step of energy per session is missing.
  - `aggregators.py` (`afap`, `alap`)
* - **As Late As Possible ends one step late**
  - The block covers steps $s_d-n+1 \dots s_d$, i.e. the step *starting* at departure is included and the charging block is shifted 10 minutes later than the plug-in window.
  - `simulate_delayed_profiles_from_sessions`
* - **Average Power can deliver less energy**
  - At half power, sessions whose window is shorter than twice the full-power duration are truncated at departure.
  - `simulate_avg_charging_profiles_from_sessions`
* - **Flexibility is a power envelope**
  - Up/down flexibility does not account for the energy consequences of activating it.
  - {doc}`../concepts/flexibility`
* - **Unknown rated power defaults to 11 kW**
  - Charging points without a rated power are simulated as 11 kW.
  - all simulators
```

## KPIs

```{list-table}
:header-rows: 1
:widths: 28 52 20

* - Limitation
  - Effect
  - Source
* - **Durations wrap at 24 h**
  - Connection time uses the time-of-day part of `end − start`, so stays longer than a day are counted modulo 24 hours.
  - `kpi/user.py`
* - **Daily energy histogram is per session**
  - `daily_consumption_dist` groups by (date, session energy) rather than by (date, charger), so it is effectively a histogram of session energies on a 0–200 kWh scale.
  - `kpi/user.py`
* - **Weekday/weekend split of availability is shifted**
  - The day-type of each folded day is computed from `weekday() + 1`, which classifies Fridays as weekend and Sundays as weekday in the City availability charts.
  - `utils.find_charger_availability`
* - **Availability is a relative index**
  - `weekday_availability` / `weekend_availability` are $1.1\max O - O$ over summed occupancy counts, not probabilities, despite the *Probability* axis label.
  - `kpi/user.py`
* - **Environment KPI units**
  - `co2_intensities_*` are sums of intensity × energy (gCO₂eq) per hour of day across the range; the chart axis reads gCO₂eq/kWh.
  - `kpi/user.py`, `plotter.js`
* - **Environment KPIs need power-mix data**
  - Two-day blocks without stored power mix are skipped silently.
  - `kpi/user.py`
```

## Data

```{list-table}
:header-rows: 1
:widths: 28 52 20

* - Limitation
  - Effect
  - Source
* - **Synthetic sessions**
  - Sessions are generated by a Monte Carlo model from empirical distributions, not measured; the ML predictor is a placeholder.
  - {doc}`../concepts/session-data`
* - **Re-generating a day duplicates sessions**
  - Only midnight occupancy is checked; running the generator again for the same day adds sessions and can create overlaps.
  - `sample_charging_sessions_ev2gym`
* - **Approximate grid topology**
  - Each column is linked to its geographically nearest MV/LV transformer, which approximates the real feeder.
  - `loaders.add_grid_connections`
* - **Single city, single country**
  - Infrastructure data covers Amsterdam; prices and power mix cover the Netherlands.
  - loaders, API modules
```

## User interface and export

```{list-table}
:header-rows: 1
:widths: 28 52 20

* - Limitation
  - Effect
  - Source
* - **Report timestamps**
  - `Load Data` timestamps start from the day before the download date, shifted by one hour and written in UTC, not from the date selected in the panel; the column labelled `EV Load (kWh)` holds kW.
  - `utils.generateLoadDataSheet`
* - **KPI sheets require load profiles**
  - KPI sheet names come from the load-profile results; download after running both.
  - `utils.generateAndDownloadExcel`
* - **Long query strings**
  - Large areas send many IDs in the URL; production servers need a raised request-line limit.
  - {doc}`../operations/deployment`
* - **Blocking `ocost` requests**
  - ReFlex polling blocks the request, with a 120-second polling deadline and 10-second individual request timeout by default. The separate Energy-Charts price request still has no explicit timeout.
  - `simulate_cost_optimal_operation`
```
