The new ReFlex API is live and still available at the same base path as before: https://drive2x.hesi.energy/services

 

Please be aware that the instance is shared with WP10 team as well and we will be using it quite heavily. So it may be that it takes long before the runs complete. If that’s a problem, please let us know, then we’ll fire up another ReFlex instance dedicated to being used by EPIOT.

 

Attached you will find the new OpenAPI specification and an example of a V2X EV input file. If the charge point has a maximum discharge power (and optionally a minimum discharge power, otherwise the minimum discharge power defaults to 0) AND if the charge session has ‘minEnergyToCharge’ property (and optionally the ‘minEnergyDuringCharging’), then the charge session is considered a V2X session.

 

It is good to be aware that the algorithm currently tries to schedule the EV with as little energy as possible, hence it will meet the minEnergyToCharge target but not the energyToCharge (because it is cheaper to charge less). It might be better to change that such that the energyToCharge is tried to be reached. If plan to fix that.

 

I am aware that the schedule is not fully correct yet. There is too much charging happening in first time interval and if there is a charge point with multiple sessions, the second one is not always scheduled correctly. We’ll look into that, but you can already try the API. If you find other bugs, please also let me know.
